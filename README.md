# 顏色寶可夢探險

和小朋友一起玩的抓寶可夢遊戲：用手機拍下身邊的東西，照片的顏色最像哪隻寶可夢，牠就會出現，再丟球把牠抓起來。

網址：https://colormon-nu.vercel.app/ （舊網址 https://endeavoryen.github.io/colormon/ 會提示搬家）

## 怎麼玩
畫面依流程切換，一次只顯示一個步驟：

1. **拍照**：按「打開相機」即時取景，或用「用手機相機拍一張」。
2. **分析顏色**：顯示照片的主要色盤。
3. **遭遇**：寶可夢從草叢跳出來。丟出寶貝球後，球最多晃三下，晃完就抓到，否則寶可夢會跳出來，再丟一次就好。
   - 寶可夢不會逃走，丟球次數不限；每失敗一次捕捉率提高 `catchBonusPerMiss`，失敗 `guaranteeAfter` 次後一定抓到。
   - 不想抓了可以按「逃跑」回到拍照畫面。
   - 沒抓過的寶可夢會先用剪影出現（名字顯示「？？？」），抓到或從球裡跳出來時才揭曉。可在圖鑑頁關閉，預設值是 `silhouetteUnseen`。
4. **抓到了**：顯示抓到的寶可夢，存進圖鑑（存在這支手機的瀏覽器裡）。見過但沒抓到的寶可夢在圖鑑裡會以灰色標示「見過」。
5. **圖鑑詳細頁**：點圖鑑裡的寶可夢，會看到整個進化家族（從最初的型態排到最後，有分支的都列出來，例如小火龍→火恐龍→噴火龍；整個家族都抓到會金框發光並標「★ 全家到齊！」，圖鑑列表裡該系列每一隻的卡片左上角也有一顆★）。資料在 `site/data/evolutions.json`，格式 `{"2":{"from":1,"to":[3]}}`，沒見過的先顯示「？？？」不劇透，點見過的可以直接跳過去）。這個檔是用 `python3 tools/build-evolutions.py` 從 PokeAPI 公開資料整理出來的，新增世代後重跑一次就好；CI 會跑 `tools/test-evolutions.mjs`：檢查小火龍、伊布、毛毛蟲等已知家族，並全部掃一遍（每個家族都是一棵沒有環的樹、from／to 互相對得上、編號都存在）。

## 運作方式
- **只看畫面中間的圓圈**（就像鏡頭對焦的點）：圓圈外面完全不算。圓圈大小和拍照畫面上的虛線圈一樣（`color.focus`，預設 0.28＝畫面 3:4 時圈的半徑是寬度的 28%），換算到照片上取出圈內，縮成 48×48，越靠近圓心權重越高，在 CIELAB 色彩空間用 k-means 抓出主色。設定在 `color`：
  - **白平衡**（`color.whiteBalance`）：用畫面裡亮、而且偏「黃橘↔藍」方向的像素估計燈光顏色，把最亮的通道當成白色來抵消（黃光下的白牆變回白色）。參考區域不夠亮（`refLowL`～`refHighL`）、或整個畫面幾乎只有一種表面（`uniformCoverage`）時只輕微校正，避免把米色、木頭、紙箱洗成灰色；鮮豔的顏色（黃色的牆）不會被當成燈光。
  - **亮度差打折**（`lightnessWeight`）：分群時亮度差只算一半，同一個東西的亮面和陰影算同一種顏色。
  - **代表色**：每群去掉最暗 20%（陰影）和最亮 10%（反光），再取比較鮮豔那一半像素的中位數，而不是平均（平均會讓顏色變混濁）。
  - 不再特別挑鮮豔的顏色（以前圈外的紅色裝飾會被當成主體，蓋過圈裡的黑色布偶）。
- 拍照前的即時提示用同一套分析（24×24），所以拍照前後說的顏色一致。
- 分析畫面會把圓圈外變暗、標出「圈圈裡」，並說明有沒有校正燈光。
- **圈裡的主體**：用圓圈的邊緣那一圈估算背景色（例如地板、桌面），圈中間和背景差很多的像素當主體（例如木地板上的黑老鼠）；主體的顏色排在前面、佔 75% 比重（`subject.weight`），分析畫面會顯示「看到紅色的東西！（背景是咖啡色）」。圈裡只有背景、或整個圈都是主體時，照舊統計整個圓圈。設定在 `subject`。
- 測試（模擬的複雜場景）：木地板上的黑老鼠＋圈外紅色裝飾 → 黑色 74%；深色布偶在圈裡、紅色和粉紅裝飾緊貼圈外 → 只取布偶的顏色（以前會被粉紅裝飾帶走）；圈裡只有木地板 → 淺咖啡色 97%；小紅球只佔圈的一小塊 → 紅色 75%。
- 每隻寶可夢有主色與配色，雙向比對：照片的顏色要在牠身上找得到，牠的顏色（尤其主色）也要在照片裡找得到。
- 顏色和屬性有關聯：每個屬性有一組代表色系（`types.json` 的 `affinity`，例如黑色、深紫對應幽靈，黑、深灰對應惡，木頭色對應地面、岩石、蟲）。挑選時先從顏色相符的幾個屬性抽一個，再在這個屬性裡挑顏色像的寶可夢（`typeWeight`、`typeWindow`、`maxTypes`）；另有 `colorOnlyChance` 的機會只看顏色，保留「紅色的球出現霹靂電球」這種驚喜。
- 只在「和最像的那隻差不多像」的範圍內隨機挑選（`similarityWindow`），再依相似度、稀有度加權；抓過的寶可夢出現機率乘上 `caughtWeight`（預設 0.3），幫忙收集完整圖鑑；同一張照片每次可能遇到不同寶可夢，但都是顏色相近的（`randomness` 越大越隨機，`sameResultPerDay: true` 則同色同天結果固定）。
- 圖片即時讀取自 [PokeAPI sprites](https://github.com/PokeAPI/sprites)，本 repo 不存放任何寶可夢圖片。

## 探索模式
不用一直拍照：相機一直開著，跟著提示在房間裡找寶可夢。

1. 拍照畫面按「探索模式」，再按「開始探險」（iPhone 會詢問動作與方向的權限）。
2. 寶可夢藏在某個方向、某個高度（可能在上面或下面）。
3. 拿著手機轉動、抬頭低頭找：畫面四邊的箭頭指出往左右或上下轉。越接近，畫面邊緣的呼吸光越閃越快（藍→黃→紅），雷達聲越密越高，Android 手機越震越強（iPhone 的 Safari 不支援網頁震動，靠光和聲音提示）。
4. 對準一下子，就會「噔噔噔」自動截下畫面，用那裡的顏色決定出現哪隻寶可夢。很暗的地方也可以，會遇到夜行性寶可夢。
5. 抓到或逃跑後回到探索，相機一直保持開著，繼續找下一隻。

感測器：
- **方向**：用陀螺儀（deviceorientation 的 alpha、beta、gamma 三個軸）算出手機背面鏡頭在空間中的方向（水平角度＋仰角），目標距離用立體夾角計算，任何握法都適用。
- 沒有陀螺儀（電腦、拒絕權限）時：在畫面上滑動轉向（左右、上下），或用方向鍵。

設定在 `config.json` 的 `explore`：`foundDeg` 對準的容許角度、`holdMs` 要對準多久、`minTargetDeg`／`maxTargetDeg` 寶可夢離起點多遠、`minPitch`／`maxPitch` 高度範圍（-32°～28°，往上往下都有，中間平視的比較多，很少要一直仰頭或彎腰）、`slowBeatMs`／`fastBeatMs` 提示節拍。

### 很暗的地方
照片或探索畫面平均亮度很低時（`night.darkL`），會出現「黑暗中有東西在動！」，從夜行性寶可夢裡挑：幽靈、惡屬性，加上 `night.ids` 列的晚上出沒的寶可夢（超音蝠、咕咕、燈籠魚、皮皮、月石、電螢蟲……）。暗處分不太出顏色，所以顏色的影響調低（`night.colorFactor`）。探索模式判斷相機有沒有在運作是看串流狀態和影像有沒有更新，不看亮度，所以暗處也能正常截圖。

## 音效
Game Boy 風格的原創音效，用程式即時合成（兩個方波通道加一個噪音通道，跟 Game Boy 的音源一樣），不用音效檔：寶可夢出現的上升琶音、揭曉的閃亮聲、丟球的「咻」、晃動的「喀噠」、抓到的小勝利曲、跳出來的「啵」、逃跑的下降音，以及探索模式的雷達聲和「噔噔噔」。右上角的喇叭按鈕可以靜音。

## 護盾（三星以上）
三星的寶可夢有 3 層護盾、四星 4 層、五星 5 層（`shields`），一、二星沒有。
- 打護盾：點螢幕上的寶可夢；鏡頭模式下也可以對著鏡頭，在寶可夢的位置揮手、跳動。每層要打 `shieldHitsPerLayer` 下（預設 3）。
- 護盾全在時捕捉率只有平常的 `shieldCatchMul`（預設 30%），每打破一層就往正常值靠近；保底次數也會隨剩下的護盾增加。
- 護盾有發光圈、碎裂特效、「鏘」和碎掉的音效，Android 會震動。

## 特別對戰（四、五星）

- 條件：這隻有護盾、星等 ≥ `battle.minRarity`（預設 4），而且玩家的圖鑑裡至少有一隻。圖鑑是空的就走原本的打護盾／丟球
- 敵人平常在畫面上半部移動；偶爾會挑釁地靠近到下半部、抖一抖停一下（最好打的時機），然後突然逃回上面：四星是猛然加速衝回去（`escapeMul`），五星是「咻」一下瞬間移動（`teleportMs`）。挑釁機率 `tauntChance`、停留時間 `tauntHoldMs`、上半部範圍 `upperFrac`。
- 俯瞰的像素決鬥場：整個手機畫面是一塊平面（XY 平面），我方（圖鑑裡隨機一隻，背面圖 `backSpriteUrl`）固定在最下面，敵人在場地裡到處移動
- **點螢幕任何地方**，我方從嘴巴朝你點的方向發射招式，飛到場地邊緣為止。敵人一直移動，偵測到來襲還有機率（`dodgeChance`）往旁邊衝刺閃開，所以可能打偏（MISS，沒有任何損失）
- **護盾要打好幾下才破一層**：`battle.hitsPerLayer`（數字＝全部一樣，或依星等 `{"default":2,"5":3}`；預設四星每層 2 下、五星每層 3 下）。一次發射不管幾顆（火的扇形、蟲的一群）最多算 1 下。血條會一格一格變紅，盾環出現裂痕（虛線→點線）。全破後回到丟球。屬性不算相剋，只影響招式
- 每次命中都有聲光＋畫面震動（`battle.shakePx`）：整個戰場閃一下招式的顏色、命中點炸出一圈、跳出「命中!」；同一層連續打中音會越來越高；破一層是玻璃碎裂音＋大一點的震動＋「破！」；全破最大。手機會震動

- 設定在 `site/data/config.json` 的 `battle`：`enabled`、`minRarity`、`foeSpeed`／`foeSpeedStep`（敵人速度，每破一層加快）、`pauseMs`（停頓）、`dashMul`（衝刺倍率）、`dodgeChance`（閃避機率）、`reactMs`（反應時間）、`cooldownMs`（連點間隔，預設 380）、`hitSlack`、`hitsPerLayer`、`shakePx`（震動幅度）、`shotScale`（招式大小倍率，預設 0.8）

## 狀態管理（不會在背景偷偷跑）
- 遊戲同一時間只在一個畫面（狀態），所有切換都經過 `show()`：拍照 → 分析 → 遭遇 → 抓到了 → 拍照／探索；任何畫面都可以開圖鑑、更新紀錄。`GAME.log` 記錄每次切換，不合法的切換會計數（`GAME.illegal`）。
- 進行中的流程（分析、出場動畫、丟球、對戰）都有編號，離開它所屬的畫面就作廢，作廢的流程不能再切畫面、也不能存進圖鑑：
  - 分析到一半離開（返回鍵、切到別的 App）→ 取消，不會突然跳到遭遇；拍到任務顏色但沒分析完，任務也不會被用掉。
  - 遭遇中去看圖鑑 → 丟到一半的球、出場動畫、對戰都停掉，寶可夢留著；按「回去抓寶可夢」回到這隻，可以重新丟。
  - 回到拍照／探索畫面 → 這次遭遇結束（就像逃跑）。
  - 丟球中切到別的 App → 球取消，回來時寶可夢還在。
  - 重新整理 → 回到拍照首頁。
- 自動測試 `python3 tools/state-qa.py`：在丟球、分析、五星出場、對戰的各個時間點模擬按返回、開圖鑑、切到背景、重新整理、探索中離開，確認不會被拉回舊畫面、背景不會多抓、沒有不合法的切換（約 75 項，每次依抓到的時間點會差一兩項；目前全部通過）。

## 介面細節（v0.38 全面檢查後）
- 用 Playwright 模擬 5 種螢幕（360×740、390×844、430×932、平板 768×1024、橫拿 844×390）＋深色模式，逐一走過所有畫面，自動檢查：左右溢出、按鈕太小（< 40px）、文字太小、對比太低、主控台錯誤。
- 手機的「返回」鍵：先關掉最上面的視窗（詳細頁、任務、休息提醒、開發者面板、甩手機確認、對戰），畫面留在原地；沒有視窗才回上一個畫面。
- 遭遇畫面的提示泡泡太長時換成兩行，不會被「…」切掉；護盾標示往下移，不會和泡泡疊在一起。
- 「更新紀錄」從標題列移到首頁版本號旁邊（小朋友用不到），標題列的按鈕因此可以維持 40px 好按。
- 橫拿手機：遭遇畫面和「抓到了」改成左右兩欄，丟球按鈕不用往下捲；相機畫面永遠維持 3:4，圓圈的位置和分析範圍一致。
- 任務卡的顏色字改成彩色小標籤（黃色字在白底上看不清楚）。

## 護眼設計
- **選球的大球**：待丟的球放大到大約畫面寬度的三分之一（`.hand`；開鏡頭的揮手甩球模式維持原本 64px，揮手判斷比較準），不用盯著小小的球；換球時柔和地淡入，不會一閃一閃；丟出去才從大球縮回一般大小飛出。點一下「丟出寶貝球！」就停在那顆（保留抽獎感）。球每 0.2 秒換一顆。
- **休息提醒**：連續玩 `eyecare.restMinutes`（15）分鐘，會跳出一隻抓過的寶可夢說「眼睛累了嗎？看看最遠的地方，數到 20」，有 20 秒倒數（`restSeconds`），也可以「先跳過」。離開遊戲超過 `breakMinutes`（5）分鐘就算休息過，重新計時。
- **顏色任務（遠方的稀有寶可夢）**：休息完、每玩 `questEveryMinutes`（6）分鐘、或沒有任務時抓滿 3～5 隻（回到拍照／探索畫面時），會跳出任務。小朋友不一定看得懂字，所以任務出現時畫面中間有一個大大的發光色塊（物品任務是大大的圖案），並且唸出「去找紅色的東西！拍下來，可能會遇到稀有寶可夢喔！」；點畫面上方的任務卡會再唸一次（音效靜音時不唸）。任務卡「去遠一點的地方找一個紅色的東西拍下來」。顏色從紅、橘、黃、綠、藍、紫、粉紅裡挑（不出灰、白、黑、咖啡，避免隨便拍地板就過）。用相機、探索模式或手機拍照拍到（圓圈裡有 25% 以上、夠鮮豔的那個顏色）→ 一定遇到三星以上（約 73% 三星、23% 四星、4% 五星）。範例圖不算。`questMinutes`（15）分鐘沒找到就消失，也可以按 ✕ 不玩，完全不強迫。
- **物品任務（可開關，預設關閉）**：圖鑑管理裡打開「物品任務」後，任務有一半機會變成「去找一個時鐘／杯子／布偶熊／盆栽…」（22 種家裡常見、安全的東西，不出車子這類要跑到外面的）。拍照（相機、探索、手機拍照）時，在手機上用 COCO-SSD 物品辨識模型（TensorFlow.js）認照片裡有什麼，**照片不會上傳**；認出任務的東西（信心 40% 以上）→ 一樣遇到三星以上的稀有寶可夢；沒認出來會說「我看到了杯子、書，可是沒有時鐘」。
  - 程式庫和模型都放在自己的網站：`site/vendor/tf-4.22.0.min.js`、`site/vendor/coco-ssd-2.2.3.min.js`（Apache-2.0，來自 npm）、`site/models/coco-ssd-lite/`（COCO-SSD lite_mobilenet_v2，用 `tools/quantize-model.py` 把權重量化成 uint8，17MB → 4.5MB，測試圖的辨識結果和原本幾乎一樣）。只有打開這個設定、而且出現物品任務時才會下載（約 6MB），之後存在手機裡（service worker 的 `colormon-model-v1`）不會重新下載。
  - 舊手機辨識可能要幾秒；載入超過 20 秒或辨識超過 12 秒就當作沒認出來，照常遇到寶可夢。
- **降刺激**：遭遇畫面的晃動幅度整體乘 `eyecare.shakeScale`（0.6）、命中閃光和五星登場的白光都調弱，對戰的閃光和震動也調小（`battle.shakePx` 3.5）。夜間調暗交給手機本身。

## 圖鑑介紹（像卡通裡的寶可夢圖鑑）
- 圖鑑詳細頁有一顆紅色的「圖鑑介紹」按鈕。**打開詳細頁不會自動唸**，按了才會：嗶嗶的開機音 → 綠色的圖鑑螢幕閃一下 → 一個字一個字打出「名字，分類。屬性。圖鑑說明」，同時用手機內建語音唸出來（語速 1.1，名字 1.0）。介紹框是白底、紅色細框。再按一次（按鈕變成「停止」）就停下來並顯示全文。音效靜音時只打字不唸。
- 文字在 `site/data/dexinfo.json`（`g`＝分類，例如「火焰寶可夢」；`t`＝圖鑑說明），第一次按的時候才下載。用 `python3 tools/build-dexinfo.py` 從 PokeAPI 公開資料整理：722 隻有官方繁體中文說明；官方沒有中文的 303 隻（大多是第 2～4、9 代）用 `tools/data/dexinfo-translated.json` 補，是從英文說明翻成適合小朋友的中文，標記 `"tr":1`。
- 「抓到了」畫面的名字旁邊也有小喇叭，點了唸名字（一樣套用唸法修正表）。

## 雙屬性
- 寶可夢可以有第二屬性（`type2`），遭遇畫面、抓到畫面、圖鑑詳細頁都會顯示兩顆屬性標籤；圖鑑的屬性篩選、寶貝球的屬性加成（捕網球打水和蟲…）也都算第二屬性。
- 第二屬性放在 `site/data/packs/type2.json`（和 `color-tweaks.json` 一樣是蓋在各世代資料包上的補充），用 `python3 tools/build-types2.py` 從 PokeAPI 公開資料整理，約 526 隻。我們的主屬性（`type`）有幾隻和 PokeAPI 不同（波波這類「一般／飛行」我們當飛行），這時第二屬性補上真正的另一個（一般）。

## 圖鑑點名字唸出來
- 圖鑑詳細頁點寶可夢的名字（旁邊有小喇叭），會用手機內建的語音朗讀（瀏覽器的 `speechSynthesis`，繁體中文 zh-TW）唸出來，不用下載音檔，方便還不認得字的小朋友。
- 唸得準不準看手機內建的中文語音，少數比較特別的名字可能怪怪的（例如「龍頭地鼠」的「地」會被當成助詞「的」）。這時在 `site/data/pronounce.json` 加一條修正：`words` 是「名字裡含有這串字就換成同音字」，`names` 是依編號整個換掉；畫面上的名字不變。音效喇叭靜音時不會唸（會提示）；唸的時候 BGM 會先小聲一下。

## 逃跑按鈕
- 場景左上角的小圓鈕（紅色離開圖示），離底下整條的「丟出寶貝球」很遠，不容易誤觸。按一下會展開成「再按一次逃跑」，3 秒內再按才離開，不按就自動收回。

## 背景音樂（BGM）

- Game Boy 風格的 8-bit 曲子，用 WebAudio 即時演奏，不用下載音檔。曲子有 `home`、`wild`、`battle`（特別對戰）、`battle5`（五星對戰，速度更快）。首頁、探索、圖鑑放 `home`，遇到寶可夢放 `wild`，特別對戰放 `battle`／`battle5`。**音量比音效小**（`config.json` 的 `bgm.volume`，預設 0.25），音效是主角、BGM 墊底
- 每首由旋律、琶音、貝斯、鼓四個聲部組成。曲子寫在 `app.js` 的 `BGM_TRK`：`chords` 是每小節一個和弦（`C`、`Am`、`B7`…），`lead` 是每小節一行旋律（`音名:長度`，單位是 16 分音符，每小節要剛好 16）；拍數不對會直接丟錯誤
- 抓到寶可夢、對戰勝利的短曲播放時，BGM 會先小聲一下
- 右上角：喇叭＝音效開關，音符＝背景音樂開關，兩個各自獨立；圖鑑管理裡也有同一個背景音樂開關。**背景音樂預設開**（記在瀏覽器裡，`colormon-bgm-on`）。喇叭靜音只關音效，BGM 另外關。特別對戰的畫面會蓋住右上角，要在進對戰前先設定
- 切到別的分頁或螢幕關掉時會停止，省電

## 鏡頭模式（揮手甩球、打護盾）
遭遇畫面預設就是鏡頭模式（沒選過模式的人；關掉或改選甩手機模式後會記住選擇），遊戲背景會變成鏡頭畫面：
- **揮手甩球**：把手放到畫面下方的寶貝球上。球的周圍有一圈分成 8 段的圓環，手碰到哪一段哪一段就亮；亮到 6 段以上並停留約 0.2 秒，球會變大、圓環變綠，這時往上甩就丟出去，甩越快球飛越快。手只是擦過球的邊緣、橫著掃過球、或正在打護盾時都不會丟球。
- **打護盾**：對著寶可夢的位置揮手、跳動。
- 不開鏡頭模式也可以直接按「丟出寶貝球！」，點螢幕上的寶可夢打護盾。

偵測方式：每秒 10 次抓一張 96×72 的小畫面，只比較寶貝球和寶可夢附近的變化（有紋理的地方門檻自動提高）；一陣子沒動靜就降到每秒 4 次。手機大幅晃動時暫停。設定在 `swipe` 和 `camera`。

圓環判斷的參數（`swipe`）：`ringSegs` 段數（8）、`ringNeed` 要亮幾段（6）、`segMin` 每段要多少變化才算有動靜（2）、`litMs` 亮多久（450）、`holdMs` 停留多久（200）、`lockMs` 打護盾後鎖多久不判斷（500）、`upRatio` 往上的比例（0.8）。`ring: false` 回到舊的判斷。

模擬測試（`tools/swipe_sim.py`，用合成畫面餵給真正的偵測程式，每種情境 180～960 次；另有「背景光影亂」情境：整體忽明忽暗、陰影掃過、樹葉光斑、曝光漸變）：手在球旁邊上下揮，誤丟率 92% → 1%；手在寶可夢上揮、橫掃過球上緣都是 0～1%；手真的放在球上再往上甩，丟出率維持 100%（背景和膚色接近的木桌 100% → 97%）。真實手機的相機畫面和光線更複雜，以上只是合成畫面的結果，請在手機上實測後再調參數。

光影抗干擾（`LiteMotion`）：每一格畫面先把整張圖分成小格，估計新舊畫面的亮度倍率並扣掉（日光燈閃、自動曝光、陰影掃過），變化不大的地方還要「邊緣真的變了」才算動作（柔邊的光斑不算）。打護盾要連續兩格、在寶可夢區域有 `minHit`（35）以上的變動量才算一下；`lockHit`（15）以上就先不判斷放手上球。`swipe.edge`（16）、`swipe.strong`（150）可調：`edge` 調小＝對和背景顏色接近的手更靈敏，但光斑比較容易誤判。取捨：手和背景顏色很接近（例如木桌）時，丟出率會從 97% 降到 84%。


> 以前的「丟真的球」（追蹤被丟進畫面的球、MediaPipe 球辨識）已經拿掉，程式還留在 `app.js` 裡（`ThrowWatcher`、`loadBallDetector`），之後要加回來比較快。

## 圖鑑
- 全部 1025 格：抓到的是彩色、見過的是灰色、還沒發現的是「？」（不透露名字和屬性）。
- 篩選：抓到的／見過／還沒發現、世代、屬性、星數；搜尋名字或編號；排序：編號、最近抓到、星數、抓到次數。各世代收集進度條。
- 點寶可夢看詳細資料：第一次和最近一次抓到的時間、抓到幾次、用過哪些球；可以放生（按兩次確認）。
- **多位玩家**：每個人有自己的圖鑑（`colormon-profiles`、`colormon-dex:<玩家>`、`colormon-seen:<玩家>`），舊版的圖鑑會自動搬到第一位玩家「我」。

## 寶可夢球
待丟的寶可夢球會像拉霸一樣快速變換（`cycleMs`，預設 0.09 秒），丟出去的那一刻才定下是哪一種（`data/balls.json`，26 種）。
- 出現機率是 `weight`：精靈球最常見（約 23%），大師球最少見（約 0.19%，平均要等 1～2 分鐘才會轉到一次）。球每 0.2 秒換一顆（`cycleMs`）。
- 每種球有小加成：`bonus`（全部都有效）、`types`＋`typeBonus`（特定屬性）、`night`（暗處）、`firstThrow`（第一球）、`perMiss`（每失敗一次增加）、`maxRarity`／`minRarity`＋`rarityBonus`（星數）、`caught`（抓過的）。大師球 `guaranteed` 一定抓到，護盾也擋不住。
- 結果畫面會顯示用哪一種球抓到；首頁「更新紀錄」裡也有每種球的效果說明。

## 更新紀錄
首頁版本號旁的「更新紀錄」可以看每個版本改了什麼，有新版本時會出現小紅點。內容在 `site/data/changelog.json`，改版時編輯它，再執行 `python3 tools/build-changelog.py` 產生 [`CHANGELOG.md`](CHANGELOG.md)（CI 會檢查兩者是否一致）。

## 圖片快取
寶可夢和寶可夢球的圖片來自 PokeAPI（放在 GitHub），PokeAPI 只允許瀏覽器快取 5 分鐘。`site/sw.js`（Service Worker）會把看過的圖片存在手機裡，之後直接使用、不再下載；網頁和資料檔則每次先拿最新版，沒網路時才用手機裡的版本。

- 相機打不開時（沒權限、剛被關掉暫時被佔用）會自動換條件重試；仍失敗也不會改掉你選的模式，按鈕變成「沒有畫面，點一下重試」。探索模式的相機由探索畫面持有，鏡頭模式只是借用，離開遭遇畫面時才會收掉，避免留下沒人管的相機畫面。

## 甩手機模式（甩一下就丟球）
遭遇畫面按「甩手機模式」打開，手機握緊，往前輕輕一甩就把球丟出去，甩越快球飛越快。不用開相機，比鏡頭模式省電；兩種模式只能開一個。
- 判斷方式：讀手機的加速度感測器（`devicemotion`），要有一小段時間（`minSpanMs`，約 40 毫秒）的持續加速度、峰值超過 `threshold`（約 1.3 g）才算甩；走路晃動、桌子被敲一下都不會觸發。
- 剛出現寶可夢或上一顆球剛落地時，會先等 `armDelayMs`（0.7 秒）手穩了才開始偵測；丟出後 `cooldownMs` 內不會連發。
- 安全：第一次打開會先跳出置中的檢查視窗（握緊、手腕帶、旁邊沒人）；甩超過 `gentleAbove` 會提醒「輕輕甩就好」。
- iPhone 要在按下按鈕時允許「動作與方向」權限；收不到感測資料時會提示改用按鈕。
- 只在遭遇畫面監聽，切到背景或離開遭遇畫面就停。設定在 `shake`。

## 圖鑑
圖鑑是蓋在畫面上的視窗：上方 ✕ 回到打開之前的畫面（瀏覽器的返回鍵一樣），下方固定「上一頁／跳頁選單／下一頁」和「回去抓寶可夢」。一頁 20 格（`dex.pageSize`），也可以在格子上左右滑動翻頁（電腦用左右鍵、Esc 關閉）。抓到寶可夢後按「看圖鑑」會清掉篩選、依編號排序，翻到牠那一頁並讓那一格閃一下。

## 省電
- 相機只在需要時開：拍照畫面按「打開相機」、鏡頭模式、探索模式。探索模式去遭遇畫面時相機先開著，15 秒沒回來就關掉（`camera.exploreKeepMs`），回來會自動重開。
- 手機切到背景或鎖螢幕：相機、運算、陀螺儀、聲音全部停，回來再依畫面恢復。
- 陀螺儀只在探索模式、動作感測只在鏡頭模式和甩手機模式時監聽。
- 拍照畫面的即時顏色提示只取中間一小塊的平均色（拍照後才做完整分析）。
- 護盾光圈、金色和彩色光芒等循環動畫只播幾次就停。
- 量測（電腦上主執行緒每秒忙碌時間）：鏡頭模式 260 ms → 約 22 ms，拍照即時預覽 113 ms → 18 ms，探索模式 66 ms → 48 ms。

## 資料與擴充
寶可夢不寫死在網頁裡，全部放在 `site/data/`，目前收錄第一到九代，全國圖鑑共 1025 隻：

```
site/data/
├── config.json            要載入哪些資料包、捕捉率、候選與機率設定、圖片網址
├── types.json             18 種屬性（名稱、顏色、圖示的 SVG path）
└── packs/
    ├── gen1.json … gen9.json   第一代（151）到第九代（120）
    └── color-tweaks.json  手動調整過的代表色，覆蓋自動算出的顏色
```

資料包格式：

```json
{ "id": 25, "name": "皮卡丘", "type": "electric", "rarity": 2, "colors": ["#F8D030", "#E85030"] }
```

- `id`：全國圖鑑編號，也用來抓 PokeAPI 圖片。`name` 是官方繁體中文名稱。
- `type`：主要屬性（一般＋飛行的鳥歸到飛行）。
- `rarity`：1～5 星。
  - 5 星：傳說、幻之寶可夢
  - 4 星：準傳說等級（種族值 570 以上的非傳說：快龍、班基拉斯、究極異獸、悖謬寶可夢……）
  - 3 星：最終形態，或不會進化但很難抓的（卡比獸、拉普拉斯）
  - 2 星：中間形態、御三家這類難抓的基礎形態、不會進化的一般寶可夢
  - 1 星：常見的基礎形態、寶寶寶可夢
  - 出現機率乘上 `rarityWeight`，捕捉率是 `catchBase`。另外有 `rarityCap` 上限（五星每次抽選最多約 2%、四星約 10%）：畫面是黑色、灰色這類顏色時，接近的寶可夢只有少數幾隻，而且常見的大多抓過（權重打折），四、五星的比例會被相對墊高，上限就是擋這個。夜晚模式（`night.rarityScale`）再把四、五星乘上 0.6、0.3，並且整個夜行名單一起抽。模擬常見顏色：1 星約 45%、2 星約 26%、3 星約 27%、4 星約 1.4%（約 70 次一隻）、5 星約 0.4%（約 250 次一隻）。4、5 星出現時會冒星星並特別提示。
- `colors`：代表色，第一個是主色。

### 自動產生資料包
```
pip install pillow
python3 tools/build-packs.py                    # 預設第 1～3 代
python3 tools/build-packs.py 1 2 3 4 5 6 7 8 9  # 全部九代（新增的資料包要加進 config.json 的 packs）
```
程式從 PokeAPI 在 GitHub 上的資料取得編號、名稱、屬性和稀有度依據，再從官方插圖自動抓出主色和配色（Lab 空間 k-means、排除描邊、提高彩度讓顏色接近大家印象中的寶可夢）。下載的檔案快取在 `tools/.cache/`。

### 手動修正
覺得某隻寶可夢的顏色不對，在 `packs/color-tweaks.json` 加一筆 `{"id": 編號, "colors": [...]}` 就好。後面的資料包可以只覆蓋部分欄位，也可以新增整筆資料。push 之前可以先跑 `node tools/validate-data.mjs` 檢查格式，CI 部署前也會自動檢查。

### 選寶可夢的機率
- 候選：和最像的那隻差不到 `similarityWindow` 的寶可夢（最多 `candidates` 隻，至少 `minCandidates` 隻）。
- 抓過的寶可夢出現機率乘上 `caughtWeight`；候選全都抓過時，顏色範圍放寬到 `widenFactor` 倍，找還沒抓過的。
- 模擬（連拍 20 次、每次都抓到）：黑色約 11 種（幽靈、惡為主），家裡的木頭色約 18 種（地面、岩石、飛行、格鬥），灰色約 15 種。

## 接硬體（規劃中）
`site/index.html` 預留兩個介面：
寶貝球只要回報「丟出」和「落地」兩件事：
- `window.onBallThrown()`：偵測到被丟出去時呼叫，畫面上的球會飛出去。
- `window.onBallLanded()`：偵測到落地時呼叫，球開始晃動並決定結果。

## 部署
正式網址在 **Vercel**（https://colormon-nu.vercel.app/），網站根目錄是 `site/`（在 Vercel 專案設定裡指定），不需要安裝或打包。

push 到 `main` 後，Vercel 會自動部署；GitHub Actions（`.github/workflows/check.yml`）會檢查資料、更新紀錄和網頁語法。舊的 GitHub Pages 不再部署，保留最後的 v0.15 只用來提示搬家（repo 改成 private 後 GitHub Pages 會自動停用）。

### 搬家（GitHub Pages → Vercel）
圖鑑存在瀏覽器裡、綁定網址，換網址資料不會自動跟過去。`config.json` 的 `home` 設定新網址和舊網址：
- 在舊網址（`home.oldHosts`）打開遊戲，拍照畫面上方會出現「遊戲搬家了！」，按「帶著圖鑑搬過去」會把所有玩家的圖鑑壓縮後放在新網址的 `#` 後面帶過去（`#` 後面的內容不會送到伺服器）。
- 新網址會問「要把舊網址的圖鑑搬過來嗎？」，確認後**合併**進來：同一隻寶可夢取比較大的次數、比較早的第一次、比較晚的最近一次，不會刪掉任何資料。
- 不能用的時候，還是可以用「圖鑑管理 → 下載備份檔／從備份檔還原」。
- 大家都搬好以後，可以在 repo 的 Settings → Pages 關閉，或把 repo 改成 private（免費方案會自動停用 GitHub Pages）。**還沒搬的手機，舊網址關掉後就讀不到圖鑑了。**

本機測試：`cd site && python3 -m http.server`，再打開 http://localhost:8000 （直接雙擊 index.html 會讀不到資料檔）。
